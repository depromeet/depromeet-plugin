# Figma 도구 설치와 관리

Figma 도구는 실행 파일을 컴퓨터의 고정 폴더에 보관하고 Figma Desktop에 등록해 사용합니다. ‘개발 플러그인’이라는 메뉴를 사용하지만 실행용 ZIP으로 설치할 때 코드를 작성하거나 빌드할 필요는 없습니다.

| 필요한 작업 | 설치할 도구 |
|---|---|
| HTML 자료를 편집 가능한 장표로 가져오기 | HTML → Figma |
| 발표 순서 확인에 필요한 정보를 추출하기 | Depromeet Flow Inspector |

필요한 도구만 설치하면 됩니다. AI에게 도움을 받고 싶다면 다음처럼 요청하세요.

```text
setup-figma-plugins로 HTML → Figma의 첫 설치를 도와줘.
Figma에서 직접 클릭해야 할 단계도 알려줘.
```

## 처음 설치하기

1. [GitHub Releases](https://github.com/depromeet/depromeet-plugin/releases)에서 게시된 버전의 파일을 확인합니다. `Pre-release`는 정식 배포 전 미리 보기입니다. 팀에서 권장하는 버전이 있다면 그것을 선택하세요.
2. `html-to-figma-v<버전>.zip` 또는 `flow-inspector-v<버전>.zip`을 내려받습니다. `<버전>`은 실제 번호를 뜻합니다. 자동 표시되는 `Source code (zip)`은 전체 저장소이므로 실행용 ZIP과 구분합니다.
3. 압축을 풀고 문서 폴더 아래 `DepromeetPlugins`처럼 계속 보관할 위치로 옮깁니다. 버전마다 폴더 위치를 바꾸지 않도록 도구별 폴더 이름에는 버전을 넣지 않습니다.
4. Figma Desktop의 디자인 파일에서 **Plugins → Development → Import plugin from manifest…**를 선택합니다. 압축을 푼 도구 폴더 안의 `manifest.json`을 선택하세요. 이 파일은 Figma에 실행 파일의 위치를 알려 줍니다.
5. Development 목록에서 도구를 실행해 창이 열리는지 확인합니다. 두 도구를 모두 쓰려면 각각 등록합니다. 설치 폴더 위치와 다운로드한 버전을 기록해 두세요.

실행용 ZIP이 없는 버전의 준비 방법과 파일 구성은 [공통 설치 안내](../../tools/figma-plugins/README.md)에 있습니다. Figma에 등록한 뒤 설치 폴더를 삭제하거나 이동하면 실행할 수 없으므로 보관하세요.

## 업데이트와 복구

먼저 실행 중인 도구를 닫고 기존 설치 폴더를 백업합니다. 새 ZIP의 파일을 **기존과 같은 위치**에 교체한 뒤 다시 실행합니다. 이전 화면이 보이거나 실패하면 의도한 폴더의 `manifest.json`을 다시 등록합니다. 자세한 교체 파일과 복구 절차는 [공통 설치 안내](../../tools/figma-plugins/README.md)를 따르세요.

이전 버전으로 돌아가려면 백업 폴더 또는 실제로 배포된 이전 ZIP이 필요합니다. 현재 도구 화면에는 배포 버전 표시가 없으므로 다운로드 파일명과 `VERSION.txt`를 보관합니다. `manifest.json`의 `api` 값은 배포 버전이 아닙니다.

## 막혔을 때 확인하기

| 증상 | 확인할 것 |
|---|---|
| `manifest.json`을 찾지 못함 | ZIP을 먼저 풀었는지, 상위 폴더 한 단계 안에 들어 있는지 확인 |
| 등록했지만 도구가 열리지 않음 | 폴더를 옮기거나 삭제했는지, 압축 파일의 일부만 복사했는지 확인 |
| 업데이트 후 이전 화면이 보임 | 새 파일을 넣은 폴더의 manifest를 다시 등록하고 실행 |
| 같은 이름이 여러 개 보임 | 새 설치가 실행되는지 확인한 뒤 사용하지 않는 등록을 정리 |
| 기존 설치 위치를 모름 | 기존 폴더를 추측해 삭제하지 말고 새 고정 폴더에 설치한 뒤 등록 |
